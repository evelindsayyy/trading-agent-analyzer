# 报告 → 新手速查表（中文版）

你的任务：拿一份 TradingAgents 报告，整理成一页纸的中文速查表，让一个完全的新手能在两分钟内读完、并且有把握照着做。你是**翻译者，不是分析师**——交易判断已经在报告里了，你只负责把它讲清楚。**不要加入你自己的市场观点。**

**全程使用中文**：无论报告本身是中文还是英文，最终速查表一律用简体中文输出。报告里的英文术语（如 Underweight、Stop Loss、FINAL TRANSACTION PROPOSAL）要翻译并解释。

## 第一步 — 找到报告

参数（`$ARGUMENTS`）可能包含：报告定位（目录路径或股票代码，可为空）+ 可选的**持仓信息**（股数，及可选成本价）。

- **目录路径**（如 `reports/WDC_20260630_120612`）→ 直接使用。
- **股票代码**（如 `WDC`）→ 找最新的对应文件夹：`ls -td reports/<代码>_*/ | head -1`。
- **为空** → 用整体最新生成的报告：`ls -td reports/*/ | head -1`，并告诉用户你选了哪一份。

如果没有 `reports/` 文件夹或找不到匹配，直接说明并停止——不要编造报告。

**持仓信息**：从参数或对话里识别用户的当前持仓（如「持有 80 股，成本 $610」「0 股」「空仓」）。这决定第三步「分步操作」怎么写（见下方「持仓自适应」）。如果用户没说，就当作「未提供」，**不要假设也不要替他编一个持仓**。

## 第二步 — 只读这些来源文件

从报告目录读取下列角色文件。**不要**读 `complete_report.md`（约 1500 行、内容重复），除非下面这些角色文件缺失。

| 优先级 | 文件 | 提取内容 |
|---|---|---|
| 1 | `5_portfolio/decision.md` | 最终 **Rating（评级）**、执行摘要、**Price Target（目标价）**、**Time Horizon（周期）**、投资逻辑 |
| 2 | `3_trading/trader.md` | **Action（买/卖/持有）**、**Stop Loss（止损）**、**Position Sizing（仓位）**、`FINAL TRANSACTION PROPOSAL` |
| 3 | `2_research/manager.md` | **Recommendation（建议）** + 编号的 **Strategic Actions（分步计划）** |
| 4 | `1_analysts/market.md` | 关键支撑/阻力价位、技术指标（MACD、RSI、均线、布林带、ATR） |
| 5 | `key_levels_cheatsheet.md` | 如果已存在，复用它的价位和触发条件表——不要重新计算 |
| 6（略读） | `1_analysts/sentiment.md`、`1_analysts/news.md` | 催化剂和需要关注的日期 |
| 7（略读） | `2_research/bull.md`、`2_research/bear.md` | 多空双方的理由，用来白话解释「为什么」 |

## 第三步 — 写速查表

用**简体中文**书写，控制在大约一页纸。严格按以下顺序使用这些小节：

1. **一句话结论** — 买/卖/持有 + 评级（如 Underweight/减仓）+ 最重要的一个理由，用新手能懂的一句话说清。然后一行紧凑信息：当前价 · 目标价 · 时间周期。
2. **数字速查** — 一个小表格：当前价、建仓/加仓区、目标价、硬止损、仓位建议。**每个数字都逐字引用自报告。**
3. **怎么做：分步操作** — 速查表的核心。编号、具体的动作及其触发条件，取自 `trader.md` 的 Position Sizing 和 `manager.md` 的 Strategic Actions。每一步写成 **「触发条件 → 具体动作 → 为什么」** 三段式，让新手照着就能做。然后**按下方「持仓自适应」规则**决定这一节的视角和落到「卖/买多少」的具体数字。
4. **为什么（白话）** — 2~4 条要点：多头理由一句话、空头理由一句话、报告最终倾向哪一边。不要留下没解释的术语。
5. **风险 & 可能出错的地方** — 哪些情况会让计划崩掉（如跳空击穿止损、财报反转、利润率均值回归）。务必包含一条关于仓位/风险的提醒。
6. **报告没告诉你的** — 最诚实的一节。列出悬而未决的问题、报告所依赖的假设，以及 2~3 件需要**读者自己**判断的事（如「55% 净利率是结构性还是周期性？」）。这一节用来代替「编造建议」。
7. **名词速查** — 每个一行白话解释，**只解释报告里实际出现过的**术语（如 MACD死叉、布林带、ATR、FCF收益率、Underweight）。没出现的不写。
8. **免责声明** — 一行：本表是对模型生成报告的白话整理，是报告日期当天的快照，**非投资建议**；价位有时效性。

### 持仓自适应（决定第 3 节怎么写）

根据用户的持仓，「分步操作」用不同视角。**先在这一节顶部用一行说明你假设的持仓**（如「假设：你当前持有 80 股，成本 $610」或「假设：你当前空仓（0 股）」），让读者一眼看清前提。

- **有持仓（股数 > 0）** → 在每一步动作后算出**具体股数**：如「减到 50% → 卖出 `round(股数×0.5)` 股，剩 `股数−卖出` 股」。优先卖成本高、浮盈薄的部分。若给了成本价，标出当前每股盈亏（现价 − 成本）和这一步大致兑现的盈亏。数字按用户真实持仓算，不要四舍五入到与股数无关的整数。
- **空仓（0 股 / 未持仓）** → 报告的减仓/卖出计划是针对**已有持仓**的，对空仓者不直接适用。**改写成「想买入者」视角**，且必须基于报告内容：
  1. **现在该不该买**：按报告结论翻译（若报告是减仓/卖出/目标价低于现价 → 通常是「先别追高」，并说明赔率为何偏下行）。
  2. **买入计划**：直接用报告给出的**重新建仓 / 触发条件**当作建仓信号（如回到目标价区放量企稳、MACD 重新金叉站稳关键均线、财报验证逻辑）。
  3. **买入止损**：给出建议的离场价（用报告的硬止损位，或现价/触发价下方的固定比例）。
  - 明确标注：这是把报告的「离场逻辑」翻译成「入场视角」，不是报告原话。
- **未提供持仓** → 用百分比表述（减到 X%），并可在每步后附一行「举例：假设持有 100 股 → 卖出 50 股」，清楚标注为**举例/教育**。

## 第四步 — 保存并展示

把速查表写入**同一报告目录**下的 `beginner_cheatsheet_zh.md`，然后在对话里直接展示给用户，并告诉他文件路径。

## 硬性规则（不可违反）

1. **绝不编造数字。** 每个价位、目标、止损、百分比、日期都来自报告。报告没写就写「报告未给出」——绝不估算。
2. **绝不推翻结论。** 买/卖/持有和评级都是报告的判断。不要软化、反转或用你自己的观点二次猜测。如果 `trader.md` 和 `decision.md` 不一致，**两个都列出来**并说明它们有分歧——不要替它们选边。
3. **可以做一般交易科普，但要单独隔离并标注。** 如果你解释一个通用概念（止损怎么运作、减仓对新手意味着什么），把它放在「名词速查」里，或清楚标注为「一般知识/科普」，绝不作为具体建议。**不要生成报告里没有的新策略。**
4. **务必保留风险 + 止损 + 仓位提醒。** 没有止损和仓位的速查表是危险的——绝不省略。
5. **白话。** 每个术语都要解释清楚。假设读者从没交易过。
6. **一次只处理一份报告，一页纸。** 如果用户指向多份报告，一份一份来。
7. **绝不编造持仓。** 用户没给股数就当「未提供」，绝不替他假设一个具体持仓。空仓时给的「想买入者」计划，必须基于报告的触发条件，并标注为「把离场逻辑翻译成入场视角」——不是报告原话，也不是你新造的策略。买入止损沿用报告的止损位或明确标注的固定比例。
